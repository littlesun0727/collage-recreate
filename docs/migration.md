# 整理范围

这是独立的新工程。原目录及其未提交修改保留原样，新工程不导入原目录的 Python 包，不共用原目录的服务数据，也不接管原服务进程。

## 保留并整理

- 当前对象分析、窗口判断、可选范围校准、照片绑定、提取合成、相框审核和交付行为。
- HTTP/yibu/Codex 模型适配、预算、缓存、结构校验、请求证据和本地坐标还原。
- 画布编辑、对话修改、素材操作、批处理队列与动图功能。
- 实际被这些功能调用的引擎模块、数据 Schema 和配置样例。
- 有效回归测试；本地凭证单独复制为被忽略的 `.env`，不写入文档或源码。

## 没有迁入的内容

- 原 Git 目录、Python 缓存、pytest 缓存、历史任务和运行日志。
- 历史离线流程报告、截图、旧实验结果、一次性评估和迁移脚本。
- 旧的首次分析、全图 boxes 和单独 materials 提示词；当前工作流不调用它们。
- `photo_window_ownership.md`、`reference_drawing.md`、`engine/analysis-rules.md` 等当前流程不再读取的旧规则。
- 从旧任务升级绑定协议、恢复旧自动微调事务、在新旧窗口流程之间切换的分支。
- 未被当前流程调用的旧恢复 helper 和单独素材观察契约。

原项目中混合的 `runner.py` 已拆成主流程、运行上下文和阶段文件；提示词先按原来真正生效的文本展开，再迁入 Markdown，消除了通过字符串替换修补旧提示词的方式。两个专门测试旧任务升级的测试随已移除的升级功能一并移除，保留并调整了原生任务续跑与完整性检查。

## 边界

这次整理不宣称解决所有视觉识别问题。窗口模型返回不合规数据时的告警/兜底、图像提取降级、抠图模型能力等仍按现有实现工作，结果需要查看任务证据。

迁移脚本、源文件哈希和验证产物保存在工程外的 `collage-recreate-v9-output/maintenance/` 与 `checks/`，不会出现在应用的日常阅读目录中。
