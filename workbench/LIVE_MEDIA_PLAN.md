# Live素材首次制作与动态成片计划

状态：2026-10-09开发与必要回归验证完成。按用户最新要求，停止调整功能样片的素材搭配和阶段记录，正式端到端效果测试由用户后续进行。验证结果见 LIVE_MEDIA_VALIDATION.md。

## 已确定的范围

客户首次提供的素材可以混合静态图片和Live视频。核心布局分析、装饰提取、静态封面制作及定稿逻辑保留。封面定稿后，以该版本为基础执行动态渲染。

成片目标时长 T = min(3秒，本任务提供的有效Live视频中的最长画面时长)。这里按本任务提供的Live素材计算，不擅自改为仅计算最终选中的素材；实际解码和抠图只处理入画视频。短视频从头循环补齐，不用末帧停住代替循环。纯图片任务继续原PNG流程。

用户已确认：按照原视频帧率逐帧抠图，不固定30fps，也不限制为30帧。保留源帧的实际时间戳及可变帧率。仅处理3秒成片时间窗中实际用到的唯一源帧，循环复用；默认无声输出，避免多个视频音轨混音。

输入目录 D:/datas/live动图素材 已读取元数据：18个H.264 MP4，时长约1.47至3.10秒，均带音轨。首版围绕此类MP4实现，原生手机Live Photo照片/视频配对及GIF/APNG可后续扩展。

## 总体路径

1. 导入图片/视频并建立源文件记录；视频生成代表帧及预览。
2. 用客户原图和视频代表帧执行原静态skill，完成分析、提取、照片绑定、封面渲染与定稿。
3. 固定封面版本与素材映射，生成独立motion.json。
4. 按统一时间轴取视频帧；需要人物出框的槽位逐帧抠图，普通相框槽位直接使用视频帧。
5. 复用定稿封面的坐标、裁切、遮罩、层级、文字和装饰，逐帧合成并编码MP4。
6. 验证时长、来源与动态效果，发布关联同一封面版本的视频产物。

不在每帧调用Agent，不重新分析布局，不重新提取装饰，不重新生成客户人物。

## 保持原静态skill稳定

优先增加媒体导入适配器：在独立媒体缓存中生成视频代表帧，然后把代表帧作为图片输入交给原prepare。静态catalog中的图片ID与原视频通过独立媒体清单关联。保留原视频哈希、代表帧哈希、准确取帧时间、方向变换和解码配置。

这样无需让原布局分析和照片匹配算法理解视频时间轴，也不需要把MP4路径直接传给Pillow。原analysis、bindings、scene仍描述封面构图。动态信息放在独立motion.json，通过scene对象ID关联视频；不改写已定稿的scene、final.png或来源哈希。

如果后续实现需要扩展prepare或catalog，只允许可选字段/入口；无视频时必须继续原代码路径。已有任务追加上传素材不得直接改动参与哈希校验的catalog，更不能靠重新build覆盖手动编辑；使用独立媒体登记及明确的新绑定版本。

## 动态数据与时间规则

新增建议产物：

- media/manifest.json：原视频、哈希、有效视频时长、画面尺寸/方向、代表帧、预览文件以及静态素材ID映射。
- chat/motion/versions/<id>/motion.json：封面render_id/scene哈希、有效素材集合、目标时长、原生时间戳策略、每个槽位的视频关联、循环规则和抠图模式。
- chat/motion/cache/：解码帧、alpha蒙版、来源与模型清单，可按源素材复用；现有修改副本自动排除chat目录，避免复制动态大缓存。
- chat/motion/versions/<id>/：final.mp4、封面关联、实际时长、逐阶段耗时及复核证据。

按视频流有效画面时间计算时长，不直接使用可能受音轨影响的容器时长。逐个解码源帧，记录实际PTS和显示时长；多视频合成使用各视频帧切换时刻的并集，按时间戳输出可变帧率视频。没有强制30fps采样或补帧，最后一帧显示时长截断到T，最终视频不超过T和3秒。时间精度为微秒。

各视频在时间t播放的位置为 (封面时间点+t) mod 原视频有效时长。默认选择源视频起始有效画面作为封面时可直接从0开始；客户另选封面时间点时保留相位，使动画起始人物姿态对应定稿封面。所有图层共用同一输出时钟。循环连接处可能出现自然跳变，首版如实保留，不擅自增加补帧、变速或淡化。

## 动态人物抠图

按槽位mode判断：普通照片框走裁切/遮罩；cutout槽位才调用人物抠图。先解码需要的唯一源帧并产生透明前景缓存，再进入合成阶段。短片循环和同素材重复使用可复用解码与抠图结果。

复用photos.py现有BiRefNet推理能力，新增独立序列处理脚本。每帧缓存键包含原视频哈希、准确取帧时间/帧内容哈希、预处理配置、模型哈希和算法版本，不能把所有帧都用同一个原视频哈希作为静态cutout缓存键。

现有make_photo会按单帧alpha边界裁紧，动态路径不能直接逐帧照搬。以定稿封面的抠图边界、缩放和锚点建立固定映射，保持原视频坐标中的人物运动；保留足够的透明图层范围，不按每帧人物边界重新居中或缩放。手动位移、旋转、遮罩和描边使用同一映射。

逐帧抠图本身不保证发丝边缘稳定。检查空蒙版、突变、漏抠、边缘闪烁及裁切；出现问题标记动态复核，不伪装成功或用生成的人物替换。是否需要时间方向的蒙版稳定处理，以真实样片验证为依据，不默认引入可能产生拖影的简单平均。

## skill具体改动

实际实现为 live_media.py（导入、原生时间轴与编码）、motion_render.py（独立计划、抠图、合成、验证）及motion_io.py（Windows并发读取时的原子写入重试）。workflow.py仅新增prepare-live和motion-render入口，原prepare/build/render行为保留。

photos.py优先复用抠图推理与照片外观函数；动态照片使用独立帧入口，保留静态文件入口。render.py若需要共享图层合成，可增加可选的帧输入接口，或抽出经过回归验证的纯合成函数，默认静态路径不变。复用已有图层导出能力缓存静态层。

不能把所有静态素材压成一张统一背景：贴纸可能在视频前面，也可能在两个视频之间。按原layer_order缓存连续静态段，视频层与静态段交替合成，保留相框窗口、人物出框、阴影与遮挡关系。

新增动态复核和发布记录，不继承封面“通过”作为视频“通过”。静态封面文件保持不变，视频编码失败保留封面与已完成缓存。

## 后端与接口

CLI本地目录导入和浏览器上传调用同一媒体登记逻辑。上传入口是新增能力，不把大视频放进现有JSON编辑请求。

实施接口：

- POST /api/uploads：创建素材批次；POST /api/uploads/:batch_id/files：流式上传单个参考图或客户素材；POST /api/uploads/:batch_id/prepare：串行准备素材并创建任务；GET /api/uploads/jobs/:job_id：准备进度与Codex接续说明。
- GET /api/tasks/:id/media：媒体类型、封面、时长、处理状态和可播放地址。
- GET /api/tasks/:id/media/:asset_id/content：按登记资源提供视频，支持Range请求和正确媒体类型。
- GET /api/tasks/:id/motion：当前封面关联的动态计划、最新视频及是否需要重渲染。
- POST /api/tasks/:id/motion/render：提交幂等动态渲染请求，携带基础封面版本。
- GET /api/tasks/:id/motion/jobs/:job_id：解码、抠图、合成、编码、验证的进度与耗时。
- GET /api/tasks/:id/motion/versions/:version_id/content：带Range的动态版本视频。

新增独立持久化动态任务队列。按用户既有偏好，端到端样本逐个串行执行；逐帧缓存支持失败重试。任务写锁、基础版本检查和发布原子性复用已有机制。不能覆盖正在被编辑的新封面。

封面在渲染期间或之后被手动/对话修改，旧视频仍关联旧封面；新版本显示“动态成片待更新”。只修改位置、文字、贴纸时复用源帧和抠图缓存，只重合成。更换视频、封面相位或抠图模型时按依赖失效对应缓存。

## 前端

素材入口允许图片与MP4混传，显示上传/准备进度、视频标识、时长与封面。素材选择仍以封面图操作，可预览原视频。

原六步流程继续展示封面制作。在封面区域增加“封面 / 动态成片”切换与独立动态进度：准备视频、逐帧抠图、合成、编码、验证。显示帧数进度和实际阶段耗时，不把封面完成误报成动态视频已交付。

首版动态预览播放后端生成的MP4，播放/暂停、进度条和下载即可；不必先实现多个视频在浏览器里的逐帧同步合成。现有SVG编辑器继续编辑定稿封面与场景，保存后标记动态输出需要更新，避免前后端各写一套动态抠图和合成逻辑。

本次上传入口完成素材准备后交接给现有Codex制作流程，不自动启动新的Agent会话。动态制作与抠图不调用SDK。先完成封面再制作视频的约束在后端执行，封面未完成不能伪报动态交付。

版本链同一封面版本下可查看对应动态成片；静态下载PNG、动态下载MP4分开。首版采用默认静音。

## 实施顺序与验收

1. 媒体适配和计划校验：18个指定MP4可导入；图片来源与视频代表帧来源清楚可追溯；纯图片任务回归。
2. 普通相框动态合成：固定封面、时长上限、短片循环、方向和原生帧时间保留；确保原装饰层级不变。
3. 人物逐帧抠图：先测一段，记录解码与每帧推理耗时，再验证固定锚点与完整序列，不预先承诺出片速度。
4. 任务队列与前端上传/播放/动态进度；支持失败重试和版本过期提示。
5. 独立样本逐个串行验证普通相框、人物出框、多个不同长度视频混排、重复素材缓存复用。
6. 验证每份成片实际视频时长≤最长输入有效时长且≤3秒；帧数正确；短片重复、长片截断；首帧构图与定稿封面对齐。
7. 检查首、中、末帧和每个循环连接处，实际播放检查边缘闪烁、人物跳动、裁切和遮挡。失败保持未通过状态。
8. 原静态任务新旧PNG逐像素/哈希一致；定稿封面与原样本文件不被动态制作覆盖；输出耗时报告与前后端验收记录。

实现只扩展素材适配与独立动态制作路径，不改变原核心分析、装饰提取和封面定稿规则。
